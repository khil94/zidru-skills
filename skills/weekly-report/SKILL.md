# weekly-report

보고서는 `~/Documents/Obsidian Vault/주간보고/<끝날짜> 김효일 주간보고.md` 한 장이다. 대상 저장소는 `repos.tsv` 에 있다. 저장소에는 파일을 만들지 않는다.

## 인자

`$ARGUMENTS`

| 인자 | 뜻 |
|---|---|
| 기간 | `1006~1008` · `10/06~10/08` · `2026-10-06..2026-10-08` 모두 받는다. 요일을 붙여 한 줄로 확인시킨 뒤 수집한다 |
| `list` | `repos.tsv` 를 그대로 보여준다 |
| `add <저장소> <구분이름>` | 경로 실존 · git 저장소 · `repos.tsv` 에 없는 경로와 이름 · `gh pr list` 가 그 저장소에서 동작, 네 가지를 확인하고 한 줄 더한다. 하나라도 어긋나면 **추가하지 않고** 어느 가지가 어긋났는지 말한다 |

인자가 없으면 기간을 묻는다.

## 1단계 — 수집

```bash
bash scripts/collect.sh <시작 YYYY-MM-DD> <끝 YYYY-MM-DD>
```

네 묶음이 나온다. `[PR]` 은 **작성자가 본인인** 머지 PR 과 그 본문·커밋 제목, `[ORPHAN]` 은 어느 PR 에도 없는 본인 커밋, `[DOCS]` 는 기간 내 수정된 `docs/`·`qa/` 파일, `[TAG]` 는 기간 내 배포 태그다.

`[WARN]` 이 나오면 PR 이 상한에 닿은 것이다. 기간을 쪼개 다시 돌린다.

## 2단계 — 행 묶기

**주제가 행이다.** 여러 PR 이 한 주제면 한 행에 모으고, 한 PR 이 여러 주제면 여러 행에 나눈다. 내용 칸은 PR 본문과 커밋 제목에서 쓴다.

구분은 `repos.tsv` 의 이름을 쓰고, 저장소에 매이지 않는 일은 그 일의 이름으로 적는다. 지금까지 `통합회원 QA` · `BE 협의` · `공통` 을 썼다. 상태는 `완료` 와 `진행중` 둘이다.

기능을 사람이 쓰는 말로 적는다. PR 제목 접두사는 떼고 근거로 번호를 끝에 둔다. 변경 줄 수는 적지 않는다.

배포 머지 PR 은 거르는 규칙을 두지 않는다. 탐지 방법이 저장소마다 달라 한 곳에서는 늘 틀린다. 자기 행을 줘도 되고 기능 행에 합쳐도 된다. 3단계가 이유만 요구한다.

작성자가 동료인데 본인이 손댄 PR 은 표에 넣지 않고 보고 끝에 한 줄로 알린다.

`[DOCS]` 와 `[ORPHAN]` 에 걸린 것은 사용자에게 보여주고 넣을 것을 고르게 한다.

## 3단계 — 쓰기

파일이 없으면 이 틀로 만든다.

```
기간: 2026-10-06(화) ~ 10-08(목)

요약 :
- 그 주의 축을 두세 줄

## 금주 작업 내용

| 구분      | 상태  | 항목 | 내용 |
| ------- | --- | ---- | ---- |

## 차주 작업 예정 기능
```

차주 절에는 지난주 보고서의 차주 절을 읽어 **끝남 · 남음 · 새로 나온 것**으로 가른 초안을 넣는다. 근거 없는 줄은 추론이라고 밝힌다.

파일이 이미 있으면 `## 금주 작업 내용` 이 **정확히 한 번** 나타나는지 단언하고 그 절만 치환한다. 없으면 **쓰지 않고 멈추고** 사용자에게 말한다. 볼트는 되돌릴 이력이 없다.

## 4단계 — 완료 기준

넷 다 돌리고 결과를 적는다.

1. 본인 작성 PR 전부를 열거하고, 표에 없는 번호는 이유를 한 줄 적는다. 이유를 못 적으면 **누락으로 보고한다.**
2. 표의 PR 번호 중 본인 작성이 아닌 것이 없다.
3. 적은 수치가 근거 파일의 값과 같다.
4. 기존 파일을 고쳤으면 앵커가 정확히 한 번이었고 앵커 밖 바이트가 전후 동일하다.

## 정지 규칙

- `repos.tsv` 의 경로가 없으면 그 저장소를 빼고 계속하되 어느 것을 뺐는지 보고에 적는다.
- 기간 내 본인 PR 이 하나도 없으면 파일을 만들지 않고 그 사실을 알린다.
- `gh` 로그인을 못 읽으면 커밋 작성자로 대신할지 묻는다.
