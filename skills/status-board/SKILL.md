# status-board

현황판은 **사용자 개인용 HTML 파일 한 장**이다. 저장소 밖 `~/.claude/status-boards/<이름>/index.html` 에 있어
이 PC 의 어느 세션이든(저장소 · 로그인 계정과 상관없이) 같은 파일을 읽고 고친다. 브라우저로 파일을 열어 본다.
이 스킬은 **판을 다루는 방법**만 갖고, **어느 판인지**는 인자로 받는다.

> 14판(2026-09-29)까지는 claude.ai 아티팩트였다. 세션마다 로그인 계정 · 조직이 달라 편집 권한이 인정되지 않는
> 일이 생겨(읽기가 요약만 오고 게시가 거절됨) 15판부터 로컬 파일로 옮겼다. 옛 아티팩트는 고치지 않는다.

폴더 꼴:

```
~/.claude/status-boards/<이름>/
  index.html        지금 판(정본)
  history/NN판.html 판을 낼 때마다 남기는 사본
```

## 판 목록

| 이름(주제) | 파일 | 저장소 줄 | 비고 |
|---|---|---|---|
| 통합회원 | `~/.claude/status-boards/통합회원/index.html` (옛 아티팩트 `S64Tq8YCiYXLbgQNqbWhS2`, 14판까지) | 회원앱(`fitgenie-client-app`) · CRM(`fitgenie-crm`) | 줄 둘 → 맨 위 저장소 탭(5판, 2026-09-22 · 로컬 첫 판 15판 2026-09-29, CRM 세션). 두 줄 모두 계획 순서 아래 「서버가 먼저 해야 하는 것」 붉은 띠(`.srv-strip` 표: 서버가 할 것 · 막는 곳 · 상태, 회원앱 6판 · CRM 10판 2026-09-28)가 있고 트랙의 막힌 칸은 `li.srv` 로 표시한다 — 각 세션은 자기 줄의 띠만 고친다. 서버 팀 일은 "우리 손 밖에서 기다리는 것" 에. 정본 — 회원앱: 그 저장소의 `docs/plans/통합회원-*` · CRM: `~/.claude/plans/wobbly-chasing-cray.md`(둘 다 로컬 전용). 템플릿 id 는 `t-app-*` / `t-crm-*`, localStorage 키 `umb.lane` · `umb.step.<lane>` |

인자가 없거나 목록에 없는 이름이면 이 표를 보여 주고 어느 판인지 묻는다.

## 이름과 줄 — 같은 이름은 같은 판

- **이름은 주제 하나에 하나다.** 목록에 있는 이름으로 새 파일 · 폴더를 만들지 않는다. 다른 저장소에서 같은 이름을 부르면 **그 판에 그 저장소의 줄이 생기는 것**이지 두 번째 판이 생기는 것이 아니다.
- **줄은 저장소다.** 판 안은 저장소별 줄(계획 순서 칸 + 패널)로 나뉜다. 줄이 하나뿐이면 표시만 하고, **두 번째 줄이 생길 때 판 맨 위에 저장소 탭(드롭다운)을 붙인다.**
- **세션은 자기 저장소의 줄만 고친다.** 다른 저장소 줄은 읽기만 한다. 글자 하나도 바꾸지 않는다.
- **처음 부르는 저장소면** 줄을 새로 만들되 기존 줄은 그대로 둔다. 구조가 바뀌므로 사용자 확인 뒤에 한다. 표의 "저장소 줄" 칸에도 더한다.
- 맨 아래 접힌 3장(손 밖 · 정한 것 · 정본)은 **공용**이다. 어느 저장소든 자기 항목만 더하거나 고친다.

## 공통 구성 — 모든 판이 같은 꼴

1. **맨 위: 계획 순서 칸들 + 「지금」 표시.** 칸을 누르면 아래 패널이 그 단계로 바뀐다(마지막 선택은 `localStorage` 로 기억, try/catch).
2. **패널** 순서:
   - "**사용자에게 무엇인가**" 한 문장 — 그 단계가 사람에게 어떤 기능인지.
   - **진행 흐름 9칸**: 설계 → 승인 → 코드 작성 → 검사 → 리뷰 → 커밋·PR → PR 리뷰 반영 → 머지 → 기기 확인. 끝은 채운 점, 지금은 테두리 점, **되돌아가 다시 한 칸은 ↺ 코랄**, 했는지 모르면 노랑 "확인 필요", 해당 없으면 점선.
   - **세부 기능 체크리스트** — 한 줄 한 기능, 상태는 `끝 · 코드 작성 끝 · 확인 대기 · 시작 전 · 서버 기다림` 중 하나.
   - 그림 하나(그 단계가 무엇을 바꾸는지, 온전한 문장 캡션).
   - **남은 일 · 우리 손 밖에서 기다리는 것 · 다음 한 가지** · 근거 링크.
3. **맨 아래 접힌 3장**: 우리 손 밖에서 기다리는 것(서버 팀 답 · 미완성 API · 다른 저장소의 일 · 계정 · 배포) / 이렇게 하기로 정했다(뒤집으면 그 위에 쌓은 것을 다시 짜야 하는 것, 영향 단계 표기) / 정본과 자료.

단계 수·칸 이름은 판마다 달라도 된다. **구조 자체를 바꾸는 것은 사용자 확인 뒤.**

## 말 규칙

- **온전한 말만.** "됨/남음/열림/해소/코드 됨/안 시작" 같은 줄임말 금지. "끝난 일 / 남은 일 / 답 기다리는 중 / 답 받음 / 코드 작성 끝 / 시작 전".
- 문서 절 번호(§4-4 같은 것)·내부 식별자는 본문에 쓰지 않는다. 링크나 "근거" 줄에만.
- 모르는 것은 지어내지 않고 **"확인 필요"** 로 남긴다. 사실은 코드·PR·서버 스펙에서 확인한 것만 적는다.
- 그림 크게, 글 적게(eli5).

## 절차

**보기만** 할 때는 파일을 읽어 요약하고, 사용자가 원하면 브라우저로 연다(Windows: `start "" "<파일 경로>"`).

**갱신**:

1. **고치기 직전에 판을 읽는다.** `index.html` 을 읽어 맨 위 도장의 판 번호(`NN판 · 날짜`)를 적어 둔다. 다른 세션이 그 사이에 고쳤을 수 있으므로 기억에 있는 사본을 쓰지 않는다.
2. **자기 저장소 줄에서 바뀐 것만 고친다.** 진행 점(9칸)이 움직인 단계, 세부 기능 상태, "손 밖" 목록, 「지금」 위치(칸의 `now` 와 스크립트의 `DEFAULT_STEP`). 판 번호 +1, 맨 위와 footer 의 날짜. 다른 저장소 줄은 손대지 않는다.
   - 파일 전체를 새로 쓰지 말고 **정확한 문자열 치환**으로 고친다. 스크래치패드에 치환 스크립트를 두고, 치환마다 "정확히 한 번 나타난다" 를 단언한다(판이 예상과 다르면 거기서 멈춘다).
3. **다른 줄이 그대로인지 대조한다.** 다른 저장소 줄의 템플릿 구간(`t-<다른 줄>-*`)이 고치기 전과 바이트까지 같아야 하고, 칸(`data-step`) · 템플릿 수가 같아야 한다. 다르면 쓰지 않고 사용자에게 묻는다.
4. **쓰기 직전에 판 번호를 다시 확인한다.** 1 에서 적은 번호와 지금 파일의 번호가 다르면 다른 세션이 끼어든 것이다. 쓰지 않고 새 판 위에서 1 부터 다시 한다(뒤에 쓴 쪽이 이기는 것을 막는 장치는 이것뿐이다).
5. **`index.html` 에 쓰고, 같은 내용을 `history/NN판.html` 로도 남긴다.** 옛 사본은 지우지 않는다.
6. **한 줄 보고.** 몇 판인지, 어느 줄의 어느 점이 움직였는지, 파일 경로.

파일은 스스로 완결돼야 한다 — `<!doctype html>` · `<meta charset="utf-8">` · viewport, 외부는 Google Fonts 만, 스크립트는 인라인, 탭 기억은 `localStorage`(try/catch). 저장소에는 파일을 만들지 않는다. 치환 스크립트 같은 작업 사본은 세션 스크래치패드에만 둔다.

## 갱신 시점

- 그 판의 **진행 점이 움직였거나 손 밖 목록이 바뀐 세션의 끝**에 한 판. 한 세션에 여러 사건이 나면 한 판으로 묶는다.
- 사용자가 "현황판" 이라고 부르면 사건이 없어도 그 시점 상태로 다시 쓴다.
- 시간 단위(매일·매주) 갱신은 하지 않는다.

## 새 판 등록

이미 있는 이름이면 등록이 아니라 **그 판에 줄을 더하는 일**이다(위 「이름과 줄」). 정말 새 주제일 때만:

1. 위 표에 `이름 | 파일 | 저장소 줄 | 비고` 한 줄. 폴더는 `~/.claude/status-boards/<이름>/`.
2. 첫 판은 공통 구성으로 만들되 계획 순서 칸과 세부 기능은 그 일에 맞춘다. `index.html` 과 `history/1판.html` 을 함께 쓴다.
3. 그 일의 저장소 메모리에는 "판 이름과 이 스킬" 만 적고 규칙을 복제하지 않는다.
